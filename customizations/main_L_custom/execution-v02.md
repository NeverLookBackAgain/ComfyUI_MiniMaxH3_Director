# Lucas v0.2 执行模式后台实现

2026-10-07。实现位于 Lucas 独立分支；提交包含执行模式 UI、后台逻辑、回归测试及去除素材与 prompt 的 v0.2 工作流模板。

## 启用

重启当前 ComfyUI 后，浏览器 Ctrl+F5，重新打开 MiniMax+H3_导演台全能工作流_v0.2。
原 v0.1 不含 lucasExecution 配置，沿用原执行流程；手动选用新增 cached_first_pass seed 模式时才启用逐段缓存 seed。

## 六种执行模式

| 模式 | 行为 |
|---|---|
| 仅一采／重抽 | 按当前导演台 seed 重新采样选中段，更新一采缓存。可用导演台原生或 SelfLift；可接脸修。主 images 输出一采结果，不重复输出 images_pre_refine。 |
| 一采＋二采 | 一采 → 二采 → 可选脸修。有效的完整二采／脸修缓存可直接复用；关闭复用则重做。 |
| 先确认一采 | 选中段中只要还有一采缺失或不匹配，本轮全部停在一采，阻断最终输出；待一采齐全后再次运行进入二采。首轮确认始终输出一采，确认后的二采轮次按“输出一采”设置输出。 |
| 仅二采 | 先核对选中段一采；缺失、参数改变或缓存无法读取时停止，不偷偷重做一采。 |
| 合成一采 | 按“选择运行”合成选中段有效一采；未开启选择时合成全部段；若保留脸修开关状态则读取有效一采脸修结果。缺段报错，不补采样。 |
| 合成二采 | 按“选择运行”合成选中段有效二采／脸修结果；未开启选择时合成全部段；可同时合成一采。缺段或参数已变时报错，不混用一采替代二采。 |

普通采样模式继续遵循原来的“选择运行”和全部／分段导出设置。全部导出时，未选中段按原流程从已有缓存／源画面填充；这与“合成二采”严格要求所选段有效二采的行为不同。

## Seed 与缓存

- `cached_first_pass` 在仅二采、确认续跑和合成模式中逐段读取一采记录的 seed。改变导演台 seed 不会把这些段误判为 seed 不匹配。
- 仅一采及需要重新一采的直接双采段使用本轮导演台 seed。二采按 inherit / offset / independent / cached_first_pass 规则选择 seed。
- passes 仍是二采轮数，与缓存复用开关独立；改变 passes 会使对应二采缓存失效。
- 新最终指纹包含一采全部已记录采样参数、模型连接见证和一采 latent 文件版本；即使同 seed 重抽，也会使旧二采失效。
- 只改脸修参数而二采未变时，复用缓存中的二采 AV latent，只重新解码、脸修和输出。
- 关闭一采输出会阻断下游 images_pre_refine 输出并省去一采成片合并、单独编码，以及无需像素放大的额外一采解码。像素放大必需的解码仍保留。
- 首次接入的旧二采缓存没有完整来源指纹，不能直接按新机制认定可复用；需要重新二采后写入新指纹。旧一采仍核对其已有字段，并在报告中标注未记录模型身份的限制。
- 原有引用上段、段间清理、单段解码前不卸载模型等逻辑保留；新一采合成同时尊重后继片段造成的接缝裁剪长度。

## 日志与预检

运行前前端自动请求后台预检；“检查运行条件”手动调用同一接口。独立 Director 运行报告显示条件和逐段状态，替换内容而非追加重复 Log。正式执行还会再次严格核验，包括前端无法获得的外接 SIGMAS。异常通过执行错误事件显示到原报告节点。后台执行判断写入原 ComfyUI 日志。

## 验证边界

- 22 项 CPU 回归：使用真实计划、实际缓存文件与执行器，仅替换 GPU 采样、VAE 解码、脸修处理。
- 14 项前端联动与提交校验。
- 现有全部 20 段缓存只读核对：HTTP 200，20/20 一采匹配，4 个不同 seed，全选可仅二采。未重写这些缓存或生成视频。
- 已观察到实际第 1 段完成 1.5M、4 步二采及解码；最终画面与音频尚未人工验收。
- 已知性能限制：仅二采仍重新构建文本／参考条件，尚未缓存这份条件；两次实际运行均出现长时间 Qwen 编码。
- 已知内存限制：普通模式选择“全部导出”仍会合并所有片段的 float32 帧；20 段混合缓存拼接已出现约 49.6GB 单次 CPU 分配失败。分段输出及整片输出的内存优化不包含在本次实现中。

运行服务需要重启后才能加载新 Python 代码。前端会检测后台版本未加载并阻止提交，不会让新 UI 静默落到旧后台。

## 2026-10-08 合成范围修订

合成保留“选择运行”范围，预检和实际视频／音频导出只读取所选段；开启选择但未勾选任何片段时报错。跳选片段按时间线顺序直接拼接，不对原本不相邻的段应用接缝修饰。输出报告记录实际合成的片段编号。

合成使用现有流式视频导出，完整视频由导演台直接保存，阻断下游 IMAGE 输出以避免重复合并／保存。普通采样的全部导出仍保留原内存限制。

本次验证：29 项 CPU 回归通过，覆盖部分一采／二采合成、未选中段缺失或改参、选中段缺失、空选区、原声范围、生成音频范围，以及实际 MP4 的跳选顺序和帧数。测试使用临时缓存及小尺寸画面，没有对生产素材重新采样。前端 JS 语法检查通过；运行服务仍需重启加载修改。
